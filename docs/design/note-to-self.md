# Private Note to self

Selecting the signed-in member in New DM opens the member’s existing singleton DM or creates it through Tower. The user-facing label is Note to self. Normal two-person DMs retain their participant and grant behavior. The native iPhone app lives in `native/` and uses the same typed Tower APIs and app namespace discovered from its workspace descriptor.

Tower accepts one distinct participant equal to the caller, or two distinct workspace members. Concurrent singleton creates serialize by workspace and actor, and reuse the earliest active matching channel across scopes. Creation rejects initial sharing grants; self channel grant additions and updates are refused. The canonical channel ID and participant array materialize through the existing channel translator and TowerSyncService; no new persisted record family or client-owned authority is introduced. The browser also filters cached singleton conversations when the active identity changes.

Self message/reply text passes through conservative URL cleanup before signature creation. The sanitizer removes an allowlist of tracking keys and `utm_` keys, preserves raw query encoding/order and unknown functional keys, and leaves recognizable signed URLs untouched. YouTube `youtu.be` links canonicalize only for an exact supported host, no custom port, a valid single 11-character path ID and no conflicting `v` query. Timestamps, playlists, indexes and fragments survive. Existing messages are not rewritten.

Self-chat pasted/picked images are re-encoded before storage prepare. Existing attachment retry/upload context guards still apply. Full decoded pixel dimensions and orientation are preserved; output is PNG. Animated images fail instead of silently losing frames. Native ImageIO output additionally filters non-rendering PNG chunks because ImageIO can synthesize EXIF on a fresh destination. Ordinary DM and document/task image handling is unchanged.

The native app discovers authorized workspaces, opens the canonical self channel, signs requests/messages locally, and reads canonical paginated messages and authenticated images. It saves offline drafts and immutable send snapshots with stable request/object IDs. A lost message response can retry the same request after relaunch. An uncertain image-prepare response pauses for reconciliation rather than blindly creating another storage object. Native setup never reads another app’s identity container.

Client source completion does not activate Tower. Verify the served browser build, activate the matching Tower implementation through its lifecycle owner, then check both directions with the real authorized identity on the phone and browser, including replies and private image access. Synthetic API/database and native mock tests are separate evidence from those live checks.
