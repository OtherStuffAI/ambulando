# Note to self for iPhone

Version 0.1, build 6. Open `NoteToSelf.xcodeproj`, scheme `NoteToSelf`, on iOS 18 or later. This dedicated SwiftUI app shares a private Flight Deck conversation through nStack; its drafts are not a replacement for Tower history.

In Settings, import your identity and choose a PIN, enter your HTTPS nStack origin, discover your workspaces, then select the same workspace and identity used in Flight Deck. Selecting a workspace opens or reuses your self conversation. Tower must support singleton DMs. Compose accepts text, photos, image files and the explicit Paste image button. History reads all canonical message pages, refreshes while the app is active, and supports replies in existing note threads. Pull to refresh after another client sends a note. The initial history view does not force a scroll jump when messages refresh.

The app has its own bundle identifier, `studio.otherstuff.NoteToSelf`, vault directory and Keychain service. It cannot read another app’s identities. Import is explicit and cannot replace an existing vault. The PIN and scalar are not persisted in plaintext. An installation-specific device-only Keychain secret and PIN encrypt the scalar with AES-GCM and PBKDF2-HMAC-SHA256 (210,000 iterations). Lock or remove clears the unlocked identity; a cold launch requires unlocking again. Signing stays inside the vault. Swift/runtime temporary copies cannot be guaranteed to be physically erased. Keep your own identity backup.

Drafts, sanitized image bytes, destination and request/object identifiers are saved atomically in backup-excluded Application Support. Text remains available while locked/offline. A send freezes its snapshot before networking; retries and process recovery retain the message request ID. An uncertain storage-prepare response pauses instead of allocating another object. Completed objects are checked for size/hash before messaging. If the authenticated metadata read for a saved object returns HTTP 404, whatever the response body, the retry prepares and uploads one fresh object from the retained bytes and keeps the message request ID; Tower’s idempotency hash covers attachment IDs, so this cannot duplicate an accepted message. A second 404 in the same attempt stops. If Tower answers a reply with 404 `thread_not_found`, nothing was recorded: the retry persists clearing only the stale thread/parent and sends once as a new note under the same request ID, so an earlier acceptance returns `idempotency_conflict` instead of a duplicate. A 404 `channel_not_found` unfreezes the draft, keeping text, images and request ID, so you can reconnect in Settings and send. Other message 404s keep the draft frozen. HTTP error notices name the request stage and Tower’s error code or a one-line error summary. If Tower reports `idempotency_conflict`, the note was already accepted under that ID: it is not resent, and its content stays as an editable new draft. Sending is foreground work; there is no promise of background delivery. Do not uninstall/reset to update: doing so deletes drafts and the app’s identity.

Known tracking parameters are removed from multiple URLs in mixed text. Unknown parameters and signed URLs remain intact. Valid 11-character YouTube short links become watch links with playback/playlist parameters preserved. Still images are decoded with orientation applied and encoded as full-resolution lossless PNG. EXIF/GPS/XMP/IPTC and PNG text/time metadata are removed, retaining only pixel/color-rendering chunks. Animated/unreadable images fail closed. PNG files can be larger than their source; the API JSON-upload fallback supports at most 8 MiB and reports a failure while retaining the draft. Storage remains private and image reads use authenticated Tower APIs.

The secure identity and transport implementation adapts the established In Dialogue/Blinkers native patterns. The pinned `21-DOT-DEV/swift-secp256k1` dependency is version 0.23.2 and retains its upstream package license. The icon is generated by `Tools/DrawIcon.swift`.

## Validation and builds

Run core checks without reading installed identities or contacting a backend:

```sh
swift test --package-path native --scratch-path tmp/native-tests
```

These checks cover metadata/orientation, URL cleanup, transport signatures, draft recovery, uncertain message retry, missing-object recovery, deleted reply threads/channels and idempotency conflicts with isolated synthetic identities and a mock transport. They do not prove authenticated physical-device delivery.

From the repository root, compile a device product:

```sh
xcodebuild -skipPackagePluginValidation -project native/NoteToSelf.xcodeproj \
  -scheme NoteToSelf -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath tmp/native-device CODE_SIGNING_ALLOWED=NO SDK_STAT_CACHE_ENABLE=NO build
```

An authorized signed build uses an existing development team/profile, without provisioning updates or changing an Apple account. Do not commit signing overrides, provisioning profiles, device identifiers or build output. Installation and launch are separate checks. Live acceptance requires an activated Tower backend, the same authorized identity/workspace in both clients, physical-device Compose/History/reply/image checks and an independent second-browser check. Keep run-specific evidence in ignored storage or the task.
